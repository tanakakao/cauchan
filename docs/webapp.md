# React Webアプリ

cauchan Webアプリは、FastAPIバックエンドを操作するReact + TypeScriptの因果分析ワークベンチです。

bochan / malchanと共通するワークベンチレイアウトを採用し、次の4工程で因果分析を進めます。

```text
Data
  -> Knowledge
      -> 手動構造を採用 ---------------------> Inference
      -> 因果探索を採用 -> Discoveryで編集 -> Inference
```

## 起動

### Windows一括起動

リポジトリ直下の `start_web.bat` を実行します。

```cmd
start_web.bat
```

バッチはcauchan専用ポートの空き状況を確認し、FastAPIの準備完了後にReactを起動します。

- FastAPI: `http://127.0.0.1:8002`
- React: `http://127.0.0.1:5175`
- OpenAPI: `http://127.0.0.1:8002/docs`

bochanは `8000 / 5173`、malchanは `8001 / 5174` を使用するため、3アプリを同時に起動できます。

### 個別起動

FastAPI:

```bash
python -m pip install -e .
uvicorn cauchan.api.app:app --reload --host 127.0.0.1 --port 8002
```

React:

```bash
cd web
npm install
npm run dev
```

ブラウザで `http://127.0.0.1:5175` を開きます。

## Data

CSVまたはExcelをFastAPIへアップロードします。

表示内容:

- ファイル名
- 行数
- 列名
- データ型
- 欠損数

新しいデータセットをアップロードすると、手動構造、事前知識、探索結果、推論結果は初期化されます。

## Knowledge

### 使用する変数

アップロードデータから、因果分析に使用する列を選択します。

選択を外した変数に関連する辺とノード制約は自動的に除外されます。また、既存の探索結果は無効になります。

### 因果構造の決定方法

#### 手動で定義

ドメイン知識に基づいてDAGを作成します。

```text
原材料 -> 工程条件 -> 物性
```

作成した構造は、FastAPIのグラフ検証に合格すれば、そのままInference画面で使用できます。

#### 因果探索を使用

Knowledge画面では探索用の事前知識を定義します。

- 必須エッジ
- 禁止エッジ
- 原因にしない変数
- 結果にしない変数

設定後、Discovery画面で探索アルゴリズムを実行します。

### エッジ編集モード

#### 因果構造

手動推論で使用する有向辺です。

#### 必須エッジ

探索結果の最終構造に存在させる既知の有向辺です。

#### 禁止エッジ

探索で認めない方向です。

同じ有向辺を必須と禁止へ同時指定することはできません。

### ノード制約

ノードを選択すると設定できます。

- **原因にしない**: そのノードから出る方向を禁止
- **結果にしない**: そのノードへ入る方向を禁止

例えば物性が原材料や製造条件の原因にならない場合、物性を「原因にしない」へ設定します。

## Discovery

### 探索手法

- **PC**: 条件付き独立性検定に基づく構造探索
- **DirectLiNGAM**: 線形・非ガウス仮定に基づく方向推定
- **GES**: スコアベース探索
- **HillClimbSearch**: 局所探索によるDAG推定

### 探索結果の種類

#### 有向辺

```text
A -> B
```

#### 未方向辺

```text
A -- B
```

PC法では、観測データだけでは方向を識別できない辺が残る場合があります。

### 探索結果の編集

探索完了後のグラフを初期構造として編集できます。

- 有向辺の追加
- 有向辺の削除
- 方向変更
- 未方向辺の削除
- 未方向辺の方向確定
- 探索直後の状態へリセット

未方向辺と同じノード間に新しい矢印を追加すると、未方向辺は削除され、指定した方向の有向辺へ置き換わります。

### 最終構造の検証

Inferenceへ進むには、次をすべて満たす必要があります。

- 未方向辺が0件
- DAGである
- 自己ループがない
- 禁止エッジと競合しない
- `forbidden_parents` / `forbidden_children` と競合しない
- 必須エッジがすべて存在する
- 少なくとも1本の有向辺がある

### 隣接行列

画面に表示する隣接行列は、探索直後の行列ではなく、編集後の最終構造から再生成します。

```text
matrix[i][j] = 1
    => columns[i] -> columns[j]
```

## Inference

### 構造ソース

Knowledge画面で選択した方法に応じて、次の構造を使用します。

#### 手動構造

Knowledge画面で作成したDAGです。

#### 探索後編集構造

Discovery画面で探索結果を編集し、検証済みにしたDAGです。

生の探索結果の `discovery_id` をそのまま使用せず、編集後の構造を因果行列へ変換してFastAPIへ送信します。

### 変数

- `factor1`: 介入変数、原因側
- `factor2`: 結果変数

推定対象は次です。

```text
factor1 -> factor2
```

### 推定手法

- **LinearDML**: 機械学習を使って交絡を調整
- **SCM**: 線形回帰に基づく推定

### 推論前の検証

- `factor1` と `factor2` が異なる
- 両変数がグラフに含まれる
- グラフがDAGである
- `factor1` から `factor2` への有向経路が存在する

有向経路がない場合、FastAPIは推定を拒否します。

## 状態の分離

Webアプリでは、次を別々に保持します。

```text
manual causal edges
required edges
forbidden edges
node policies
raw discovery result
edited discovery result
inference result
```

そのため、探索結果を編集しても、Knowledge画面で作成した手動構造は保持されます。

## APIとの対応

| 画面操作 | API |
|---|---|
| データアップロード | `POST /api/v1/datasets` |
| 手動構造・制約の検証 | `POST /api/v1/graphs/validate` |
| 因果探索 | `POST /api/v1/discovery` |
| 編集後構造の検証 | `POST /api/v1/graphs/validate` |
| 因果効果推定 | `POST /api/v1/inference` |

## 現在の制約

- FastAPI再起動でデータセットと探索結果が消えます。
- ブラウザ再読み込みで画面上の編集状態が消えます。
- ノード位置はサーバーへ保存しません。
- 複数の探索結果を履歴として切り替える機能は未実装です。
- 観測されていない交絡や測定誤差を自動的に解決するものではありません。
